## Behaviors and acceptance

Start returns 202/queued, with message, run/event, instructions and idempotency completion in
one transaction. Concurrent same-key requests return one run; another active run in the same
conversation conflicts. Failed writes roll back the dedup claim. Keys are scoped to owner,
operation and resource; changed canonical body conflicts, including optional context changes.

Input receipt lookup precedes stale revision. A new input appends a user control-plane message,
wakes/fences the waiting run and saves its original acceptance atomically. It does not borrow a
worker lease. Receipt retries after completion/server restart return that original response.

Approval checks ownership before revision/binding/state; it compares exact server proposal,
arguments digest and tool version. Last decision wakes only once no unexpired pending proposals
remain. Acceptance/rejection invoke no MCP. A new worker revalidates/consumes accepted bindings.
Cancel remains an idempotent durable intent; clients cannot supply execution status/history.

Connections require explicit host grant and independent DB app/tenant/private-owner/enabled
checks. POST accepts only serverId. Revoke uses revision CAS, hides foreign resources, and
invalidates later dispatch. No inline credentials, command configuration or OAuth flow.

Context selections require owned ready connections before a bounded read-only host preparer.
No default resource/prompt access or external URI fetch. Media references require an explicit
scoped host authorization hook before forwarding to a provider. Denial rolls back run/dedup.
All operations use injected authenticated bearer identity, never actor/app claims in payload.

## Reuse/provenance and limits

Direct reuse: P02 withDeadline/createFingerprint, P04 transactionPool/run/approval/message/
checkpoint/idempotency stores and immutable SQL guard, P05 engine. Existing P02 provenance
applies; no newly copied legacy source or third-party implementation. New wiring is project code.

Host must implement real bearer verification, operator server/credential policy, scoped context
preparation/media grants and deployment cursor secret. Callbacks are read-only/bounded and may
hold the atomic command transaction briefly. Provider-specific unsupported content remains
governed by P05 adapters. Local tests are not hosted CI, live model evaluation or deployment.

Capabilities advertise eventReplay false. No daemon/poller or HTTP start CLI added. Snapshot
cursor is ready for P06-02, which must still verify future sequence/retention and project public
durable events. No rate limiter/retention sweeper/artifact storage/delegated agents/desktop now.
