## Key decisions for downstream lanes

- **Owner check comes first.** A different actor/app/tenant gets `not_found` before revision or
  status checks, so record existence does not leak. Tenant-less rows never match tenant scopes.
  Storage uses `tenant_key = ''`, which avoids NULL semantics in unique constraints.
- **Compare-and-set revisions** start at 1 and increase by 1. Stale or future values return
  `revision_conflict` with `currentRevision`, which maps to API `409 REVISION_CONFLICT`.
- **Tool-call ledger**: `dispatching` is persisted before the MCP call, and `attempts` increments.
  - There is no way back to `ready`.
  - `retry_wait` requires `known_not_applied` evidence.
  - `unknown -> succeeded|failed` requires `reconciliation` evidence.
  - `dispatching -> cancelled` is invalid; the outcome must be recorded.
  - Approval-required calls cannot skip `awaiting_approval`.
- **Run settlement**: terminal runs require every tool call to be settled, and `completed`
  refuses `unknown`. Cancellation is idempotent durable intent (`cancelRequestedAt`) and is a
  no-op on terminal runs. Terminal runs have no outgoing transitions, so late results cannot
  revive them.
- **Approvals**:
  - Bind run, tool call, the full `McpToolRef` (including definition version) and the SHA-256
    `ArgumentsDigest`. Contracts only validate 64-hex; the application computes it with
    `shared/fingerprints` and domain/version.
  - Acceptance checks expiry. Consumption is single use, checks expiry and exact binding.
  - `ApprovalStore.consumeForDispatch` commits approval consumption and the tool call move to
    `dispatching` atomically.
- **Events**: gap-free per-run sequence from 1, appended in the same transaction as the state
  change (`events` parameter on every write port).
- **Error style**: expected conflicts are `StateResult` values; infrastructure faults reject.
