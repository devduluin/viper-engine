## Behavior

- **Request**: Chat Completions with `stream: true` and `stream_options.include_usage`.
  - System messages map to `system`; user content to text / `image_url` (inline images as data
    URLs); JSON to text.
  - Assistant tool calls map to `tool_calls` (arguments JSON-encoded), and tool results to
    `role: 'tool'` messages with `tool_call_id`.
  - This API has no `is_error`, so a non-success outcome is stated in the content
    (`[tool outcome: unknown]`).
  - `max_completion_tokens`; `reasoning_effort` only when configured; `responseSchema` →
    `response_format: json_schema`.
- **Decisions and failures**:
  - Function tool calls make `tool_calls`; text alone makes `final`.
  - `length` → `output_limit`, so a truncated tool call is never executable.
  - `content_filter` and `refusal` → `permission`.
  - Invalid argument JSON, non-function tool calls and empty output → `invalid_response`.
- **Errors**: typed SDK classes (abort, timeout, connection, 401, 403, 429, 5xx, length/filter
  errors, other API errors). Provider text is never echoed.
- **Streaming**: `text_delta` events, plus `tool_call_delta` with the call ID remembered per index
  (later fragments carry only the index), then `usage`. Each is awaited.
- **Config**:
  - The model is **required** (`VIPER_OPENAI_MODEL`); no model name is guessed.
  - `OPENAI_BASE_URL` (https, or http on loopback) allows compatible endpoints.
  - The key is read only from the environment and never appears in errors.
- **No reasoning replay**: OpenAI does not need provider-opaque blocks for Chat Completions, so
  there is no replay cache.
