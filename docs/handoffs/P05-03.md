## Behavior

- **Directory checked on every acquire.** `pool.acquire(scope, connectionId)` asks the directory
  each time, even when a session is cached. As a result:
  - a foreign scope or an unknown ID gets `not_found` and never reaches the server;
  - `revoked`, `authentication_required` and a disabled server are refused, and the cached
    session is released.
  The same check applies on resume, because resume also calls `acquire`.
- **Credentials**:
  - The `McpCredentialPort` resolves per connection owner. There is no fallback to a shared
    account or to another user's connection.
  - HTTP 401 at connect triggers exactly one `refresh(rejected)`. A second 401, or a failed
    refresh, records `authentication_required` in the directory; later acquires are refused
    without contacting the server.
  - A bearer token travels only as `Authorization`. An environment credential reaches only the
    stdio subprocess, which never inherits the parent environment (a test proves a parent
    variable does not leak).
- **Mid-session expiry**: a 401/403/404 response to `tools/call` is a pre-handling HTTP rejection,
  so the result is `error` (`authentication_required` / `permission` / `connection_unavailable`),
  never `unknown`.
- **Revocation**: `pool.revoke` writes to the directory first, then closes the session (and the stdio
  subprocess). Gateways handed out earlier see a closed session (`connection_unavailable`).
- **Resources and prompts stay application-controlled.**
  - They are not exposed to the model.
  - `readResource` / `getPrompt` first check that the URI/name is in the server's own listing
    (paged, max 20 pages). Otherwise they return `not_found` without sending a request, so
    model or tool output cannot make the engine fetch an arbitrary URI.
  - A tools-only server stays valid: resources/prompts report `unsupported` while tools work.
- **Directory (Postgres)**: one owner predicate covers actor/app/tenant plus private-server
  ownership (`mcp_servers.owner_actor_id`, previously documented as a repository duty).
  - `markAuthenticationRequired`: `ready → authentication_required` only.
  - `revoke`: idempotent and final, with `revoked_at` set. Revisions step +1 under the existing
    trigger.
