## Decisions and compatibility

Migration0012 required only for learning; prior migrations unchanged. Three new tables (21 engine
tables plus ledger). Existing HTTP/API/events/context checkpoints unchanged. Host still owns pool,
authentication, connection deadlines and message ingestion; no model-generated scope or user identity.
Every proposal binds clean persisted completion, current feedback revision, source/final message,
owner and execution-ledger digests. Digest is integrity data, not an independent authorization grant.
Accept requires selected post-run owned user text exactly matching candidate; note stays user_asserted.
Failed/unverified/partial/unknown/cancelled attempts cannot be promoted despite positive feedback.

Every replacement feedback atomically stales older pending/accepted proposals. Original promoted
note is tombstoned only if not independently edited/deleted since acceptance. Stale/rejected items
stay terminal. One run lock serializes feedback/proposals/review; lock order run -> proposal -> note.
All effects/audit are in one transaction, including database-triggered invalidation, so no background
maintenance job is necessary. At most32 lifetime proposals/128 feedback revisions per run.

Candidate/source/ledger metadata are retained for review. Tombstones are not global data erasure;
immutable user history, proposal candidate text and audit metadata remain. No raw MCP outputs or
provider credentials are copied into learning tables/audit. Context still treats notes as untrusted.
