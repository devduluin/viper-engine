## Design

- **Repositories never import `pg`.** They take a `SqlPool`. Bootstrap passes a `pg.Pool`.
- **Every write is one transaction**:
  1. lock the run row (`FOR UPDATE`), so lock order is always run → tool call → approval;
  2. decode the row and apply the pure applier from `contracts/state/transitions.ts`;
  3. write with `WHERE revision = $before`;
  4. append events from `last_event_sequence + 1`.
  Conflicts are returned before any write, so a `StateResult` error never commits a partial change.
- **Ownership**: rows are read by ID, then compared with `checkOwnership`. A foreign or missing row
  is `not_found`.
  - A proposal on a connection that is not the caller's own, or whose server does not match, hits
    the composite FK and is mapped to `not_found`.
  - A second live approval hits the partial unique index and is mapped to `invalid_transition`.
- `RunStore.transition` reads every tool call status under the run lock (settlement).
  `requestCancellation` writes nothing and appends no events when the run is unchanged.
- `consumeForDispatch` checks approval consumption and the tool call's `dispatching` transition
  before writing either, then writes both, so they commit together or not at all.
- **Time** crosses as exact integer epoch ms (`timestamptz 'epoch' + ms * 1 millisecond`;
  `round(extract(epoch) * 1000)`). `tenant_key ''` maps to an absent `tenantId`.
- **Runner**: one transaction holding `pg_advisory_xact_lock`. It creates `viper_engine` and
  `schema_migrations` on a fresh DB. It refuses:
  - an existing schema without a ledger;
  - checksum drift;
  - unknown applied versions.
  Checksums are computed over LF-normalized text.
