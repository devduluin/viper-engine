## Behavior

- **Append** (`MessageStore.append`), in one transaction with lock order run → conversation:
  - compare-and-set on the conversation revision;
  - gap-free positions;
  - owner-only (`not_found`).
- **Pairing across the whole conversation**:
  - a tool result must answer an earlier, unanswered call;
  - call IDs are never reused;
  - system instructions are never persisted as history (`invalid_transition`);
  - the DB unique index still guards one result per call.
- **Run messages** (`runId`): the run must belong to this conversation.
  - **A terminal run refuses late messages**, so a late tool result cannot revive or extend it.
    Ledger outcome reconciliation stays available through `ToolCallLedger`.
  - The lease is checked (and, after the P04-02 review rule, a claimed run requires the current
    lease). Run events commit in the same transaction; events without a run are refused.
- **Read**: cursor pages by position plus the conversation revision, from one snapshot.
- **Checkpoint** (`CheckpointReader.load`): one `REPEATABLE READ READ ONLY` transaction returns
  - the run;
  - the conversation revision;
  - the full history (bounded by `maxMessages`, default 10 000, otherwise a RangeError rather than
    an unbounded load);
  - the run's tool calls and approvals (with snapshots);
  - `lastEventSequence`.
  
  All of it reflects the same instant, so a client can stream events after `lastEventSequence`
  without gaps or duplicates. Owner-only.
- **Resume never redispatches completed effects**: the checkpoint carries ledger statuses. The P04-02
  state machine plus fencing prevent re-dispatching settled or in-flight calls.
