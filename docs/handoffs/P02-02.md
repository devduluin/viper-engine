## Behavior preserved and intentional changes

**delay**
- Preserved: resolves after the duration.
- Changed: rejects invalid durations (negative, NaN, Infinity, and values above 2^31-1, which
  Node would otherwise fire after 1ms).
- Changed: zero still schedules a macrotask. Abort rejects with `signal.reason`, and the timer
  and listener are always cleaned.
- Renamed: `sleep` is now `delay`.

**withDeadline**
- Preserved: the message `<operationName> timed out after <ms>ms` and timer cleanup.
- Changed: takes an operation *factory* `(signal) => Promise` instead of an already-started
  Promise. On timeout or caller abort the signal is aborted with the same reason
  (`DeadlineExceededError` or the caller's reason).
- **Timeout is not cancellation.** Work that ignores the signal keeps running; a test proves this.
  A late rejection of that work is absorbed and never becomes an unhandled rejection.
- Operation errors pass through unchanged. Synchronous throws become rejections.

**withRetry**
- Preserved: capped exponential backoff `base * 2^(n-1) + jitter` with legacy defaults.
  `DEFAULT_RETRY_TIMING` corresponds to legacy `maxRetries: 2`.
- Changed (the counting unit):
  - `maxAttempts` counts total calls (`maxAttempts = maxRetries + 1`).
  - Success returns `{ value, attempts }` with the actual call count, fixing the `withRetrySafe` miscount.
- Changed (the retry decision):
  - `shouldRetry(error, attempt)` is required, so the caller decides whether repeating is safe,
    including for writes. No message-text heuristic is applied.
  - The policy is not consulted after the final attempt.
- Changed (failure): rejects with `RetryError { reason: 'exhausted' | 'not_retryable',
  attempts, cause }`. Legacy rethrew nonretryable errors raw; now the original is kept as `cause`.
- Changed (injected dependencies):
  - `random`, `wait` and the `onRetry` observer are injectable. Observer exceptions are swallowed
    so that logging cannot change control flow.
  - Abort rejects with `signal.reason` and starts no further attempt.

**mapBounded / settleBounded**
- Preserved: bounded concurrency and input-order results.
- Changed: a sliding window replaces chunk barriers, so a slow item no longer stalls the next
  chunk; the ceiling is still enforced.
- Changed: concurrency must be a positive safe integer.
- Two explicit modes:
  - `mapBounded` is fail-fast. The first failure stops new launches; in-flight siblings are
    awaited before it rejects with that first error. Legacy `Promise.all` rejected immediately
    and orphaned the siblings.
  - `settleBounded` returns per-item `fulfilled | rejected | skipped`.
- Abort: no new launches; unstarted items are `skipped`. `mapBounded` rejects with the reason
  only if items were left unstarted. Failures never roll back items that already ran.
