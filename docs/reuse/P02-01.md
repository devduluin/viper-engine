## P02-02: async component extraction from S01

Source dependency: `appLogger` singleton. Remove that import; inject an optional narrow observer
and timing/cancellation dependencies where needed. Application/bootstrap composition supplies
Clock.now values or narrow timing callbacks from the agreed P01 port. Shared utilities receive
primitive instants/functions; they do not import contracts or invent a second domain Clock type.
No source file from the 463-line module moves
intact into the new project.

| Component | Selected exports/logic | Proposed destination | Preserved behavior |
| --- | --- | --- | --- |
| A1 | `sleep` | `src/shared/async/delay.ts` | Resolves after requested delay |
| A2 | `withTimeout` | `src/shared/async/deadline.ts` | Bounds waiting and clears its timer |
| A3 | `withRetry`, `RetryConfig` concepts | `src/shared/async/retry.ts` | Bounded attempts and capped exponential backoff |
| A4 | `processInBatches` | `src/shared/async/batch.ts` | Bounded concurrency and input-order results |

Intentional changes to implement and test:

- A1: validate finite nonnegative delay; support AbortSignal and remove listeners/timers on settle.
- A2: prefer an operation factory receiving a signal to a prestarted Promise. Propagate caller
  abort and request cancellation on timeout where supported; timeout alone never proves remote
  cancellation or rollback. Do not retry a write because the wrapper stopped waiting.
- A3: caller-provided retry policy decides safety, including idempotency/side effects. The old
  string-message heuristic is not imported as runtime policy. Inject delay/jitter for deterministic
  tests; preserve the original cause and report actual attempted-call count. Document whether
  the new option counts attempts or retries, with explicit conversion from old maxRetries.
- A4: reject zero/negative/noninteger/nonfinite concurrency instead of risking a nonprogressing
  loop. Cancellation stops new work; already-started operations retain known/unknown outcomes.
  Specify fail-fast versus per-item outcomes explicitly; do not imply failure rolls back siblings.

Not selected from S01: `withRetrySafe`, `withRetryAndTimeout`, `raceToSuccess`,
`raceWithTimeout`, `processWithRateLimit`, `SimpleCircuitBreaker` and global defaults.
The current `withRetrySafe` returns maxRetries + 1 even after first-attempt success.
`withRetryAndTimeout` may launch another operation while the timed-out operation is still active.
`raceToSuccess` iterates the passed Promises rather than observing the first success as it occurs;
`raceWithTimeout` has no timer cleanup. Do not recreate these convenience APIs without a need.

Characterization requirements before claiming adoption:

- Delay/deadline: success/error/abort, explicit zero-delay semantics, invalid durations,
  timer/listener cleanup and underlying work that settles after the caller times out.
- Retry: immediate success reports one attempt, nonretryable error calls once, bounded exhaustion,
  deterministic backoff/cap, abort while sleeping, and unsafe write policy refusing repeat dispatch.
- Batch: empty input, stable order, active-count ceiling, invalid concurrency, partial failure,
  and no additional launches after cancellation.

## P02-03: time, text tokens and result values

### S02: empty-value predicate

Selected: `isEmptyPrimitiveValue` -> `src/shared/results/emptiness.ts` with no dependencies.
Preserve null/undefined/blank-string/empty-array as empty; zero, false and empty object remain
nonempty according to this narrow predicate. Test all those cases plus nonempty containers.
This is not an execution verdict; a read returning [] can succeed.
`readResultErrorField` is deferred: its truthiness/coercion behavior is not a machine error contract.

### S03: current-time grounding

Selected: formatting logic in `describeCurrentDateTime` -> `src/shared/time/current-time.ts`.
Preserve deterministic Intl-based date/time grounding for a supplied instant. Replace the implicit
new Date() and hardcoded Jakarta/WIB assumption with an injected instant/Clock and explicit
locale/IANA timezone from trusted context. Derive a correct timezone label rather than labeling
all zones WIB. Locale defaults can be chosen by application configuration, not routing rules.

Tests: fixed instant under different host TZ settings, UTC/Jakarta date boundary, another IANA
zone including DST, invalid instant/timezone and deterministic output for supplied locale.
Do not copy location registries or install temporal extraction as part of current-time formatting.

### S04: approximate text token count

Selected: `TokenEstimator.estimate` algorithm used by `estimateTokens` ->
`src/shared/tokens/estimator.ts`; original exports depend on the static class, not external packages.
Extract a small function/configuration component rather than copying the full class/API.
Preserve empty text zero and a positive bounded estimate for nonempty text, using documented
character/word weighting as approximate preflight accounting. Validate finite positive factors.

Intentional change: coefficients/settings are injected or explicit; usage from the actual provider
remains authoritative. Text-only helpers must not pretend to price images/media or structured
message framing accurately. `estimateMessages`, `estimateMessageTokens`, `estimateDetailed` and
provider presets are deferred; they assume simple role/content strings and fixed framing overhead.

Tests: empty/whitespace/Latin/Indonesian/non-Latin/emoji text, monotonic sane counts for chosen
fixtures, option validation, exact deterministic rounding and explicit approximate labeling.

## P02-04: MCP boundary and new canonical fingerprint

### S05: error/content normalization

Selected: `classifyMcpProtocolFailure`, `classifyMcpCallToolFailure`,
`unknownMcpProtocolFailure` and the useful extraction logic from `unpackMcpCallToolPayload`.
Proposed destinations: `src/adapters/mcp/errors/signals.ts`, `classify.ts`, `payload.ts`.
No imports exist in the source. Internal helpers/types must be mapped to agreed P01-02
MCP/outcome/content contracts rather than duplicating that lane's public types.

Preserve stable HTTP/OAuth/network error normalization, `isError` handling, bounded inspection
and an unknown fallback. Retryability is transport guidance only: runtime policy decides whether
another call is safe. Classification cannot grant access, switch user/account or approve a write.

Intentional changes:

- Preserve structuredContent and all supported content blocks, including non-text blocks.
  The current unpacker first returns parseable joined text, even if structuredContent exists,
  and returns a scalar instead of keeping the complete envelope. Do not copy that precedence.
- Parsed text can be supplementary fallback, not silent replacement of authoritative structured
  data. Conflicting/malformed blocks remain observable and bounded.
- Distinguish trusted transport status from provider payload hints. A payload category cannot
  erase a transport authentication failure. Define precedence explicitly with P01-02 owner.
- Current normalization searches message text and substring codes; limit authoritative signals
  to documented code/status fields, and treat free-form message hints as diagnostics only.
- Keep localized safe text in an adapter/presentation mapper, not in the core outcome contract.

Tests: 401/403/404/408/429/5xx, OAuth/network codes, conflicting code/status, isError true/false,
no code, nested/cyclic/deep input, malformed/JSON/plain/multiple text blocks, structured-vs-text
conflict, non-text media/resource blocks, and write retry policy remaining independent.

### S06: fresh approval digest, not an adopted legacy hash

Reject legacy `createHash` default 8-character MD5, `hashParams`/`paramsEqual`, and
`generateCacheKey` for approval identity/integrity or exact parameter equality.
Source sorts only top-level keys, uses ambiguous delimiter serialization, and collapses
null/undefined; nested object insertion order changes fingerprints.

P02-04 should implement a new validated recursive canonical encoder and domain/version-separated
SHA-256 digest under `src/shared/fingerprints/`. A digest is not a signature or authorization
token. Snapshot scope/tool/version/final arguments remain trusted server-side data.
Cache-only hashing and hardcoded city/date/timezone lists are not selected.

Tests: recursively reordered keys equivalent; meaningful nested values/types differ; delimiters
inside values do not collide by construction; arrays retain order; unsupported/undefined/cyclic
values rejected according to contract; domain/version prefixes separate uses; no short digest.
