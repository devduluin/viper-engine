# P05-01 integration review: Anthropic

Reviewer: Codex, 16 November 2026. Owner implementation: Claude.
Disposition: APPROVED after the fixes below and independent offline verification.
Scope: first provider (Anthropic); the separate OpenAI P05-01b handoff is not reviewed here.

## P1: replay cache could mix private provider blocks across owners

The original cache fingerprint contained only normalized assistant content/tool calls. Two
conversations producing the same answer therefore shared the opaque thinking/signature entry.
This could send one actor's private provider blocks in another actor's request.

Fixed in `src/adapters/models/anthropic/replay-cache.ts` and `to-request.ts`: fingerprints bind
actor/app/tenant, conversation, run, model, tools, response schema and the exact preceding history.
The assistant's own generated message ID is deliberately absent; lookup uses the history prefix
before that assistant turn. Cache entries are deeply frozen JSON snapshots, bounded by both
1000 entries and 16 MiB aggregate bytes; oversized blocks are not retained.

SDK output has non-enumerable parsed-output helpers. The snapshot preserves actual serialized
provider fields, including signatures, without treating SDK helpers as protocol JSON.

Regression: identical answers cannot replay thinking across actor/app/tenant/conversation/run/
model/history changes. Existing same-context verbatim replay still passes. Deep immutability
and byte eviction are verified separately.

## P1: a stream or awaited observer could outlive the model deadline

SDK request timeouts alone do not bound every wait during stream consumption/backpressure.
A body that never ends, or an observer that never settles, could hold `generate()` indefinitely.

Fixed in `gateway.ts`: reuse P02 `withDeadline` around stream consumption, final response and
awaited delta/usage observers. Use the earlier of the request deadline and a positive host limit
(default 600000 ms); propagate cancellation and explicitly abort the stream during cleanup.
Timeout maps to a typed retryable failure. Timers/listeners are cleaned by the shared helper.

Regression: stalled stream, caller cancellation and a stalled usage observer all terminate.
This bounds adapter waiting; it cannot forcibly terminate arbitrary host callback code.

## P2: failure metadata and incomplete responses were too permissive

- API error type/refusal category were provider-controlled strings in public failure messages.
  They are now omitted; only typed failure codes and HTTP status remain.
- Unknown/missing stop reasons no longer produce executable decisions. Usage goes through the
  existing safe-integer parser; overflow cannot enter budgets as valid usage.
- Bootstrap SDK retry default changes from 2 to 0, avoiding hidden automatic retries beneath
  the runtime's model-attempt accounting. Explicit host retry configuration remains supported;
  production wiring must account for any nonzero policy. No environment file was loaded/edited.

Regression: sentinel private metadata is absent, unrecognized completion reasons and overflowing
usage fail closed, configuration tests enforce the zero-retry default.
