# P04-02 integration review

Reviewer: Codex, 16 November 2026. Implementation owner: Claude.
Disposition: APPROVED after fixes and independent isolated PostgreSQL verification.

## P1: an omitted lease bypassed fencing

`leaseConflict` returned success whenever the optional token was absent, even after takeover.
Tool/approval proposals also lacked lease admission. A worker could omit the token and mutate
a run whose execution belonged to another worker.

Fixed: once a run has ever been claimed, execution mutations require its current lease,
including proposals, run/tool transitions, step/model writes and approval consumption.
Unclaimed offline/store fixtures remain supported. User cancellation remains a separate
authenticated control-plane action; it does not require borrowing an execution lease.

A new explicit `RunStore.wake` admits only waiting -> running under owner/CAS checks, clears
the paused lease and raises the fence. A new worker can claim it; the paused holder cannot
write. This avoids making durable input/approval resume impossible under stricter fencing.
Wake grants no tool permission and does not consume approvals or dispatch anything.

## P1: expiry relied on a potentially stale event timestamp

Writes/renew/release could use an old `at` to pass an expiry check. Release did not check expiry
at all. Fixed: sample database wall time after the run lock and check the later of database
time and caller time. Renew/release also compare against database time; release now requires
`at`. Backdated writes cannot revive a lapsed lease before another worker takes over.

## P1: old idempotency owners could modify a replacement reservation

Expiry/abandon could replace a reservation with an identical key and fingerprint. The original
request could then complete or delete that replacement because no generation was checked.
A conflicting INSERT followed by SELECT also raced with abandon deleting the row.

Fixed: migration 0006 adds a UUID claim identity; `started` returns `claimId`, which is required
for complete/abandon. Expiry creates a fresh identity. All three operations serialize on one
owner/operation/key advisory transaction lock, including deletion/recreation.
Old requests cannot change a replacement even when its payload fingerprint is identical.

## P2: audit admission and failure-code sanitation were incomplete

Step/model starts now reject terminal/cancel-requested runs while settlement of existing work
remains possible. Model finish validates usage through the existing parser and accepts only
known failure codes, preventing raw provider text from being persisted as a sanitized code.

  composition/deterministic resource identity in P06; this port alone cannot make two commits atomic.
