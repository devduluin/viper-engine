# P06-03 integration review

Disposition: resolved; P06-03 DONE. Codex integration, 17 November 2026.
Self-review with regression evidence, not an external audit.

## Findings and fixes

1. **Poison-run starvation across hosts.** A setup failure followed by immediate lease release
   let workers reclaim the oldest failed run. Persist safe per-run backoff under its live fence
   before release; claim SQL checks database-time availability. Two hosts and auth/restart tests
   prove healthy progress and no model invocation for the deferred run. No memory-only fallback.
2. **Cancellation depended on failing setup.** Even cancelled runs performed MCP configuration
   before cleanup. Resolve an empty cleanup plan after current cancellation check; stored state
   still governs recovery/budgets. A deferred auth-failed run cancels without discovery/provider RPC.
3. **Heartbeat after shutdown/loss.** The guard kept rescheduling renewal while an uncooperative
   failure callback drained. Stop timer rescheduling once lost/closed. Actual DB regression holds
   the callback past shutdown timeout and verifies no further renewal, then waits for actual drain.
4. **Shutdown timeout claimed too much.** stop is bounded but done represents actual completion.
   Timeout leaves phase stopping and a timeout flag; it does not report stopped/close the caller's
   pool. Fatal close errors reject done safely. Signal helper owns/removes only its own listeners.
5. **Private context duplicated on adoption.** Hosts could already supply persistedRunInstructions;
   automatic loading then duplicated IDs and failed context assembly. Snapshot and merge by ID,
   dedup exact content, reject conflicts. Actual SDK test sees static and saved context once.
6. **Expiry races.** Global approval updates followed by a separate wake could miss work or clash
   with decisions. Maintenance selects/locks eligible runs first, expires due proposals and wakes
   atomically; two sweepers wake once, a live pending sibling prevents early wake. No dispatch.
7. **Background fault/observer behavior.** Slot and maintenance failures back off independently;
   observer calls are bounded and cannot retry settled work. Events/classification use closed
   failure codes, never raw SQL/SDK text. Configuration/timers/concurrency are validated.
