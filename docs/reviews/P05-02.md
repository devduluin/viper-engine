# P05-02 integration review: MCP lifecycle and tools

Reviewer: Codex, 16 November 2026. Owner implementation: Claude.
Disposition: APPROVED after the fixes below and independent offline verification.
Scope: session, transports, catalog, aliases and tool dispatch. P05-03 access/pooling/persistence
and the separate OpenAI adapter remain pending their own review.

## P1: tool arguments and owner bindings were mutable across discovery

The original gateway retained the host's owner/connection object and sent the original tool
arguments after an awaited catalog read. Reusing/mutating those objects could change the
binding or arguments after validation and before dispatch.

Fixed in `src/adapters/mcp/client/snapshot.ts`, `connect.ts` and `gateway.ts`: validate trusted
scope, snapshot/freeze connection and tool reference, and deeply parse/freeze arguments before
the first await. A caller cannot rebind the constructed gateway by reusing its context object.

Regression: mutating input during discovery still sends the original `{a:2,b:3}` and returns 5;
mutating the host's original owner/connection leaves the original owner authorized and the
replacement denied. Shared JSON/identity validation is reused without duplicate validators.

## P1: catalog invalidation could race the final dispatch check

Even when `catalog.all()` returned a valid snapshot, a list-change between its resolution and
the gateway continuation could allow the now-stale definition to be dispatched.

Fixed in `catalog.ts` and `gateway.ts`: expose the invalidation generation and compare it around
the discovery await, followed by existing ownership/capability/liveness/cancellation checks.
A changed generation is conservatively not dispatched (`not_found`); reload can happen later.

Regression: invalidate the catalog immediately before discovery resolves; the server call log
proves that the requested tool was not invoked.

## P1: discovery waits did not share the caller's total deadline

Per-page SDK timeouts did not cap the total discovery/pagination/dispatch operation. A hung
catalog operation could also ignore AbortSignal and prevent the gateway from returning.

Fixed in `timing.ts`, `gateway.ts` and `failures.ts`: P02 `withDeadline` covers the whole operation,
including discovery and advertised-context checks. The earlier of caller deadline and positive
host timeout wins. Invalid clock/deadline values are refused. Child cancellation reaches SDK
requests, and a final check prevents late discovery continuations from dispatching.

Dispatch evidence is retained: a timeout before sending is `error`; after sending it remains
`unknown`, since an external action may have happened. No retry/re-dispatch was introduced.

Regression: hanging discovery terminates for list and call; the server log shows no tool send.
Existing mid-call timeout/abort/crash tests continue to require `unknown`.

## P2: close and invalidation observers could delay cleanup

Mark sessions closed before awaiting transport shutdown, and isolate invalidation observers
from one another. A throwing host observer cannot prevent other listeners from invalidating
their caches or block cleanup. Session connect/request timeouts must be positive finite timers.

Regression: closing immediately rejects new work; a throwing observer does not suppress the
next listener. Existing stdio test still verifies that close terminates the actual subprocess.

- Real SDK transports: stdio child process and an ephemeral loopback HTTP fixture, no external
  MCP server, credential access or dependency installation by this reviewer.

- Source/function/complexity/layer/cycle gates pass. No root export or runtime-layer imports.

  Runtime wiring, approved writes and restart behavior remain P04/P05-04 responsibilities.
