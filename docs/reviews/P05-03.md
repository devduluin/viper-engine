# P05-03 integration review: MCP access, resources and prompts

Reviewer: Codex, 16 November 2026. Implementation owner: Claude.
Disposition: APPROVED after lifecycle/access fixes and independent verification.

## P1: revocation and shutdown could miss an opening session

Original revoke/closeAll inspected only live sessions. A concurrent credential resolve or
initialize could subsequently publish an authorized connection after revocation/shutdown.
Credential waits also had no total deadline.

Fixed in `src/adapters/mcp/client/connection-pool.ts`: owner-scoped pool keys, opening-generation
identity, total connection-open deadline, admission after credential resolution/initialize and
before publication. Revoke/release invalidate pending generations; closeAll closes the pool and
awaits bounded pending opens. Late completions cannot publish. Late credential resolution is
refused before connect; an initialization already in progress is closed when it completes.
Older pending finalizers cannot erase a newer opening. Failed generations are retired.

## P1: already handed-out connections did not recheck durable access

Acquire re-read the directory, but cached gateway/catalog references could continue after an
external DB revoke/disable/endpoint change until the caller explicitly acquired again.

Fixed: a host authorization callback re-reads the directory at catalog access and immediately
before tool dispatch, including after awaited discovery. Resource/prompt get checks again after
advertisement. Scope/connection revision/server configuration bind the session; changed bindings
retire it. The gateway's whole-operation deadline also bounds these checks.

A mid-session HTTP 401 retires the rejected session. A later explicit acquire can resolve and
refresh once during connection establishment. The failed tool is never automatically repeated.
Calls already sent when access changes retain unknown-outcome semantics when interrupted.

## P2: prompt arguments could change after advertisement

Snapshot the selected prompt name/arguments before awaiting its listing. Capture selected
resource URI as well. The advertised name/URI and actual request now refer to the same input.
Request timeout validation also happens before opening a direct SDK session.
