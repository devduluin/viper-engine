# P08-04: release audit findings

Reviewer: GPT,18 November2026. Scope: risk-based source review across engine layers, prior review
invariants, executable negative cases, full scripted regression, build/clean-install evidence and
dependency advisories. This is a code/engineering review, not a production penetration test.

Disposition: five reproduced code defects fixed; two dependency advisories removed from the
resolved tree. Final acceptance/evidence is in [release review](../release-review.md).

## A01 - P1: worker timestamps could take over a live lease

[Lease store](../../src/adapters/persistence/postgres/lease-store.ts) compared candidate expiry
against caller `at` and also derived claim/renewal expiry from it. A worker one day ahead could
steal a valid lease. A backdated renewal could return success with an expiry already in the past.

Reproduced both failures before the fix. Claims now use PostgreSQL clock_timestamp for eligibility
and duration. Renewals use DB time and never shorten the current expiry; existing conservative
write/renew/release fencing still rejects a caller timestamp beyond expiry. The `at` argument
remains for interface compatibility and is validated for claims. Clock skew cannot grant takeover;
correct host clocks are still needed for local deadlines, reporting and availability.

[Regression](../../tests/integration/postgres/audit-leases.test.ts) covers ahead/behind workers,
actual DB expiry, higher fences and backdated renewal. Older lease tests now expire the actual DB
lease explicitly instead of advancing a fake worker timestamp to simulate database expiry.

## A02 - P1: approval proposal admission omitted the lease check

[ApprovalStore.propose](../../src/adapters/persistence/postgres/approval-store.ts) accepted a
lease field but never checked it under the run lock. A previous worker, or a caller omitting its
lease, could create a new pending approval/event on an already claimed run.

Reproduced successful unauthorized proposal creation. Admission now calls the existing
leaseConflict before proposal/event writes. Unclaimed offline fixtures retain their supported
behavior; owner decisions remain separate control-plane actions.

[Regression](../../tests/integration/postgres/audit-approval-fence.test.ts) verifies omitted,
stale and DB-expired leases are refused without approval/event writes, while the current lease
can propose. Journal already injects its lease, so valid durable approvals continue to work.

## A03 - P2: a truncated SQL suffix could certify an older database

A directory containing migrations1..12 is contiguous. Combined with a DB at12,
[assertSchemaReady](../../src/bootstrap/database.ts) could report ready for code requiring13.
Missing-directory checks alone did not catch a missing final migration file.

Reproduced that false readiness. [schema-version](../../src/bootstrap/schema-version.ts) now pins
the reviewed build requirement13. Migration execution, startup and build packaging check that
the available SQL reaches exactly that version. Adding a migration requires updating the pin;
build fails if this is forgotten. Historical SQL/checksums were not rewritten.

[Regression](../../tests/integration/postgres/audit-schema-assets.test.ts) proves an old DB plus
truncated assets cannot pass readiness or bootstrap an incomplete schema. Complete compiled assets
still pass the fresh DB/host smoke. Packaging also rejects dangling symlink output files.

## A04 - P2: disappeared owner access left an idle MCP session open

[Connection pool](../../src/adapters/mcp/client/connection-pool.ts) returned not_found when the
directory hid/deleted a connection, but left the previous session in its live map. Directory checks
already prevented new dispatch; the defect was session/subprocess lifetime and retained resources.

Reproduced an open session after the owner lost access. acquire now retires only that scope's
cache key before returning not_found. A different scope cannot close the owner's session.
[Regression](../../tests/contract/mcp-client/audit-retirement.test.ts) uses an actual HTTP MCP
fixture and proves both retirement and isolation.

## A05 - P2: Anthropic completion reason could contradict executable content

[Response interpretation](../../src/adapters/models/anthropic/from-response.ts) accepted tool_use
blocks with end_turn, or a successful final with tool_use and no calls. The OpenAI adapter already
rejected the equivalent contradiction. A structurally complete but contradictory reply should
remain invalid rather than becoming an executable decision or a claimed final result.

Reproduced both cases with the real SDK/scripted transport. The adapter now requires agreement
between tool blocks and completion reason, preserves available usage, and returns invalid_response
on mismatch. [Regression](../../tests/contract/model-anthropic/audit-stop-reason.test.ts) verifies it.
Refusal/truncation handling, opaque replay and optional prompt caching retain existing tests.

## A06 - dependency advisory remediation

Registry audit initially reported Ajv moderate and esbuild low; no high/critical entries.
Pinned Ajv8.17.1 ->8.18.0 and tsx4.21.0 ->4.23.15, resolving esbuild0.27.7 ->0.28.2 without an
out-of-range override. Lockfile and both fresh/main installations were validated.

Ajv's fix is in the [maintainer release](https://github.com/ajv-validator/ajv/releases/tag/v8.18.0),
addressing the [$data ReDoS advisory](https://github.com/advisories/GHSA-2g4f-4pwh-qvx6).
This engine does not enable $data; exploitability in its configuration was not demonstrated.
The [esbuild maintainer advisory](https://github.com/evanw/esbuild/security/advisories/GHSA-g7r4-m6w7-qqqr)
concerns its Windows development server; this engine uses tsx transformation and does not launch
that server. Both versions were updated regardless of that limited exposure.

Final npm audit on18 November2026:0 reported advisories across the resolved tree. This is the
registry's result at that time, not a guarantee against future or unreported vulnerabilities.
Raw before/after JSON is retained in artifacts/p08-04-npm-audit*.json.
