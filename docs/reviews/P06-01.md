# P06-01 integration review

Disposition: resolved; P06-01 DONE. Codex integration, 17 November 2026.
Self-review with regression evidence; not an independent external audit.

## Findings and fixes

1. **Atomic request identity.** Separately creating the run then completing dedup could leave a
   second runnable identity after a crash. Reuse transactionPool over one transaction for dedup,
   queue/event, initial message and private instructions. Forced post-message SQL failure proves
   all rows roll back; six concurrent requests create one run. Active-conversation check is locked.
2. **Control input versus worker lease.** A previously claimed run cannot append run-originated
   messages without a lease. Clarification appends an authenticated user control-plane message
   under run/conversation locks and wakes/fences in the same transaction. Receipt is durable;
   exact retry after completion/restart returns its prior acceptance before stale revision checks.
3. **Framework object prototypes.** Fastify params/query objects have framework-owned prototypes.
   Passing them directly through the strict JSON-record parser returned 500. Copy own entries at
   the HTTP boundary; keep strict JSON parser unchanged. Invalid query/authority cases now fail 400.
4. **Approval concurrency and stale revision.** Re-read approval after locking the run; check its
   own revision before binding/state. Wake only after the last pending decision. Tests verify
   exact args, rejection without dispatch, multiple approvals and actionable stale currentRevision.
   Rejection is no-side-effect evidence; the established core can complete a truthful answer.
5. **Route-length mismatch.** Default framework parameter limit was shorter than the v1 opaque
   ID contract. Configure encoded-path allowance while parseId retains the 256-character bound.
   Full-length Unicode and reserved/slash IDs are covered.
6. **Private and bounded projection.** Explicit allowlists exclude system instructions/endpoints/
   secret refs/raw SQL. Saved instructions load only into trusted worker context. Long text splits
   without losing Unicode; overflowing content blocks remain explicit JSON evidence. Output
   schema validation rejects accidental private/unsupported wire fields before serialization.
7. **Selection/media authority.** Context connection ownership/auth/enabled are checked before
   host preparation. Resource URI/prompt policies remain explicit host responsibilities. Reference
   media needs a scoped host grant before forwarding; no implicit URI fetch or bearer fallback.
   Denials create no run/idempotency claim. Cursors bind owner/kind/resource/expiry and signature.
8. **HTTP lifetime.** No request-abort signal reaches a durable worker. A real socket disconnect
   during command preparation still commits; worker completes after HTTP close. HTTP close does
   not close DB pool, request cancellation or dispatch a tool.
