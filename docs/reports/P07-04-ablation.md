# P07-04: simple loop vs advisory checklist

Status: offline scripted ablation completed; final repository/integration gates pending.
Command: `npm.cmd run planning:report`. Date:17 November2026. Synthetic data only.

## Predeclared design

Six unique fixtures: simple read, two dependent reads, missing input, approval-gated write,
unknown tool outcome and failed tool. Three paired repeats each, alternating baseline/planned order:
18 pairs /36 executions. Fixed model responses do not inspect plan presence. Expected statuses,
tool arguments and call counts are defined before running; no live tuning or judge model involved.
Repeated runs test reproducibility, not independent statistical samples or stochastic confidence.

Baseline is the existing loop with its context budget; the planned variant adds the same small
host-authored checklist through user-role evidence. No extra model, tool grant or execution stage.
Raw requests/statuses/final text/tool arguments/order/local loop timings are in
artifacts/planning/p07-04-trials.json. Report/source/fixture/package hashes and raw checksum are in
artifacts/planning/p07-04.json. These files are generated by the command, not handwritten baselines.

## Observed results

All18 paired invariant checks PASS: statuses/final output/arguments and call counts preserved.
Waiting-for-input and waiting-for-approval remain pauses; partial unknown and failed error remain
unsuccessful completion. There is no change to model decisions because replies are scripted.

## Decision

Keep the baseline simple loop as default. The experimental `createPlanEvidence` seam is explicitly
opt-in and remains off unless a host installs it. **Automatic planning is DEFERRED**: no measured
live semantic improvement justifies the input overhead. This is not a quality win over baseline,
V4, Hermes or a live model. No task-specific routing heuristic is introduced based on these cases.

The seam is available for controlled paired live evaluation on tasks that actually need a checklist.
Before enabling a host workload, freeze independent cases/budgets/model/tool settings, count all
helper calls and compare quality/usage with state resets. Fewer steps or more structured output
alone are not evidence of benefit. See [evaluation plan](../evaluation-plan.md).

Deterministic unit/integration results separately validate ownership, role/budget and exact approval
after restart; they do not convert this fixed-response experiment into a semantic benchmark.
Read [guide](../bounded-planning.md) and [handoff](../handoffs/P07-04.md).
